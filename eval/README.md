# 評価セットの形式（eval/questions.csv）

評価セットは開発者が手で作る（CLAUDE.md の「保護されたファイル」）。このファイルは形式の取り決めだけを書く。

- 文字コード：UTF-8（BOMなし）。VS Code で編集する。
- 区切り：カンマ。値にカンマや改行が入るときは `"` で囲む。
- 1行目は次のヘッダーにする。

```
qid,question,gold_pages,gold_mode,answer,answer_value,answer_unit,q_type,evidence,notes
```

## 列

| 列 | 必須 | 書き方 |
|---|---|---|
| `qid` | ○ | `q001` から連番。一度付けたら振り直さない。消した質問は欠番にする |
| `question` | ○ | 利用者が実際に打ちそうな日本語。**スライドの見出しや文言をそのまま写さない**（テキスト検索が言葉の一致だけで有利になるのを防ぐ） |
| `gold_pages` | ○ | 根拠ページの ID（`data/pages.jsonl` の `page_id`、例 `toyota/fy2025_full/p005`）。複数は `;` 区切り |
| `gold_mode` | ○ | `all`：すべてのページが必要（例：通期と1Qの比較）／`any`：どれか1つで足りる（同じ値が複数ページに載っている）。ページが1つなら `all` |
| `answer` | ○ | 文の形の正解 |
| `answer_value` | 数値の質問のみ | 数値だけ。カンマ・単位・「約」は付けない。負の値は `-3.1`。**資料に表示された桁数のまま**書く（`15.2` と表示されていれば `15.2`） |
| `answer_unit` | `answer_value` があるとき | 資料の表記どおり：`億円`、`百万円`、`千台`、`%`、`pt` など |
| `q_type` | ○ | 何を聞くか：`lookup`（1つの値を読む）／`compare`（2つ以上の値の比較・差・比率）／`trend`（推移・傾向）／`structure`（図の構造：パイプラインの段階、内訳の関係など） |
| `evidence` | ○ | 答えがどこにあるか：`chart`（グラフ）／`table`（表）／`diagram`（図）／`text`（本文の文字） |
| `notes` | | 迷った点や、解釈の余地がある点のメモ |

業界・企業・資料をまたぐかどうか・答えがテキスト層にあるかどうかは、`gold_pages` と `data/pages.jsonl` から自動で求めるので書かない。

## 採点のルール

- 数値の質問は `answer_value` と `answer_unit` で自動判定する。表示された桁数で一致すれば正解（`15.2` が正解なら `15` は不正解）。
- 評価セットは dev / test に分けない。そのかわり、プロンプト・k・チャンクサイズなどの設定は**評価を回す前に決めて固定する**。結果を見て調整し直した場合は、README にそのことを書く。

## 配分の目安

- 全80問（5業界 × 16問）。まず40問で一度すべての方式を回す。
- `evidence` はグラフと表を多めにし、図と本文の文字も少し入れる（比較の基準として）。

## 形式チェック

```powershell
uv run python scripts/validate_eval.py
```

ヘッダー、必須の列、決められた値、`qid` の重複、ページ ID の存在、数値の書き方を確認する。質問や正解の中身は見ない。
